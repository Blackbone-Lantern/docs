# Documentation Guidelines

This document defines the documentation standards used across all Blackbone Software projects.

---

## General Principles

Documentation should be:

- understandable
- concise
- maintainable
- easy to navigate

---

## Official Documentation

Whenever a technology, framework, library or tool is introduced for the first time in a document, its name should link directly to the official documentation.

### Good

- [React Native](https://reactnative.dev/docs/)
- [TypeScript](https://www.typescriptlang.org/docs/)
- [GitHub](https://docs.github.com/)

### Avoid

React Native

Official Documentation:
https://reactnative.dev/docs/

---

## Internal Links

Whenever possible, reference related documents inside the Engineering Playbook.

Example:

- [Branching Strategy](branching-strategy.md)
- [Engineering Philosophy](philosophy.md)

---

## Keep Documents Small

One topic per document.

Split documents when they become difficult to navigate.

---

## Engineering Principle

> Good documentation should answer questions before they are asked.
